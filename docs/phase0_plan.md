## 1. 规则与环境引擎（阶段1交付物）

### 1.1 规则基线（日式立直麻将，以天凤/雀魂竞技规则为准）
- 136 张牌（万/筒/索 1-9 各4 + 风牌/三元牌各4），无花牌；赤五万/赤五筒/赤五索各1（赤宝牌）。
- 半庄战（东南两圈）、亲家连庄（含流局听牌连庄）、1本场=300点。
- 和牌条件：4面子+1雀头 或 七对子 或 国士无双，且有役；役满、累计役满按规则计。
- 核心役种：门清自摸、立直、一发、断幺九、平和、役牌、一杯口、三色同顺、一气通贯、混全带幺九、七对子、对对和、三暗刻、混一色、纯全带幺九、二杯口、清一色、国士无双、四暗刻、大三元、小四喜、大四喜、字一色、清老头、九莲宝灯、累计役满等；天和/地和/人和视平台可选。
- 振听（舍牌振听/同巡振听/立直后见逃振听）禁止荣和；食替（现物喰い替え）禁止；流局四类（九种九牌、四风连打、四杠散了、四家立直）；荒牌流局按听牌与否结算；多家荣和按头跳（atamahane）只取上家优先一家；流局满贯（nagashi mangan）按平台可选；切上满贯（kiriage mangan）。
- 立直：门前清听牌、支付1000点立直棒、立直后手摸切自动、一发与里宝牌（杠宝牌）结算。
- 杠：明杠（大明杠/加杠）、暗杠；杠后翻新宝牌指示牌；抢杠、枪杠规则；四杠流局。
- 点数：符+番计算（20-110符、1-4番及满贯/跳满/倍满/三倍满/役满），点棒结算、飞人（负分即终局）、西入可选。

### 1.2 环境实现方案
- 规则内核：采用 mahjong 2.0.0（向听/和牌/符番/振听/杠/流局判定），禁用其不完整部分，自研牌山/回合调度/鸣叫优先级/点棒结算。
- 外壳：RiichiEnv（gymnasium 风格 + 批量向量化自对弈模式）：step(actions) 支持摸切/手切/立直/吃/碰/杠/荣和/自摸/流局/九种九牌；返回 34×C 特征张量、合法动作掩码、奖励。
- 规则校验套件：≥200 条手工构造单元测试（振听3类、食替、国士13面、抢杠、四杠流局、本场/立直棒结算、役满累加等），并与 mahjong 库交叉校验；这是'完整对弈环境'的验收标准，全部通过才进入训练。

## 2. 架构选型（推荐方案）

选定：方案A改良 —— 单主干 + 多头共享 CNN（Suphx 同构，合并五模型）

### 2.1 选型理由
1. Suphx 已验证：CNN（3x1 卷积，保留34列牌种语义）在 Tenhou 十段级别有效，天凤稳定段位超99.99%玩家；本机 12GB 显存、单卡条件下训练成本可控。
2. 五模型分治的劣势（模型间协调复杂、四张小网络反复前向）由共享主干 + 4个二元头 + 1个弃牌头消除：一次前向同时输出弃牌分布与所有动作概率，参数量降为约1/5，自对弈决策延迟更优。
3. Transformer（方案B）上限高但训练不稳定、对单卡RL代价过大。采用'先CNN跑通全流程，再做 Transformer 消融'的迭代策略：阶段5若时间与算力允许，以相同特征接入 GPT-2 级 decoder 或 cross-column attention 头做对照实验。

### 2.2 网络结构
```
输入: C × 34 × 1（C=特征通道数，列=34牌种，行=1，无池化——保列语义）
  ├─ 3x1 Conv, 256 ch
  ├─ 残差块 × 50（每块: 3x1 Conv 256 → ReLU → 3x1 Conv 256，带 skip）
  └─ 共享特征 (256 × 34)
       ├─ 弃牌头: 3x1 Conv 32 → Flatten → FC 1024 → FC 256 → Softmax(34)（合法动作掩码）
       ├─ 立直头: Conv 特征 + 候选牌特征 → 2 logits（可用性掩码）
       ├─ 吃头  : 同上 2 logits（输入含顺子组合编码）
       ├─ 碰头  : 同上 2 logits
       ├─ 杠头  : 同上 2 logits
       └─ （RL阶段附加）全局奖励预测器: 2层 GRU(512) → 线性 → 预测终局名次奖励
```

### 2.3 特征通道设计（阶段1细化，此处为基线）
- 手牌 4 通道（第 n 通道 = 该牌种持有 n 张）；副露、宝牌指示牌、各玩家牌河（含摸切/立直/宝牌标记通道）、杠、立直棒、点数分桶、剩余牌数分桶、场风自风、局数、亲家标记等：基线约 200 通道。
- 前瞻特征（look-ahead）：按 Suphx 方式 DFS 搜索'切某张后向听/和牌概率与得分'约 100+ 条 34 维向量，逐步补入，最终对齐 Suphx 的 838/958 通道量级（作为阶段2/3 增强开关，做消融）。

### 2.4 参数量与推理延迟估算
- 主干：50 × 2 × (256×256×3) ≈ 19.7M + 输入卷积 0.6M + 各头 ≈ 约21M 参数。
- FLOPs ≈ 3 GFLOPs/前向（fp16），RTX 5070 理论 >100 TFLOPS → 纯计算 <1 ms；实测预估单次决策 1–3 ms（批量推理摊薄后 <0.5 ms），完全满足自对弈（向量化批量）与在线对战。
- 显存：fp16 训练 batch 512 + 梯度检查点可控制在 12GB 内；推理占用 <1GB。

## 4. 训练流程设计

### 阶段3 — 监督学习（SL，先得到基线模型）
- 数据：~6000 万决策样本（1M 局 × ~60 决策/局）。
- 目标：弃牌头 softmax CE（仅人类实际执行的合法弃牌作标签）；立直/吃/碰/杠头二元 CE（只在人类有该选择权的局面构造样本，标签=是否执行）。
- 优化：AdamW(lr 3e-4 → 余弦衰减)，warmup 5k 步，混合精度 fp16，batch 512，梯度裁剪 1.0；epochs=2–3，早停依据验证集弃牌 top-1 准确率。
- 基线验收：弃牌 top-1 ≥ 50%（Suphx 类似口径 70%+，天凤人类间一致性约 60–70%，此为合理区间）、top-5 ≥ 85%；不足则回退特征/结构。

### 阶段4 — 强化学习（PPO 自对弈）
- 环境：向量化自对弈（8–16 并行牌局/worker），PPO + 熵正则（Suphx 式分布式RL在本机单卡以共享内存采样近似）。
- 奖励：终局名次奖励（1/2/3/4 位 → 按点差缩放）+ 全局奖励预测器（GRU，按当前局+历史局预测终局奖励，作为密集奖励信号）+ 立直/和牌过程奖励。
- 可选增强：神谕引导（oracle 可见全牌墙，逐阶段剥离信息）作为阶段4的开关项；对手池（历史 checkpoint 混战）防策略坍缩。
- 规模：目标 ≥1 亿环境步（12GB 单卡预估 2–5 天，逐步放量）；每 2000 万步出 checkpoint 并跑固定对手回归赛。

### 阶段5 — 评估与迭代
- 离线：留出 10 万局人工牌谱的决策一致率、自对弈天梯胜率/安定段位模拟（Elo + 天凤段位换算）、与随机/规则基线对比。
- 人工评估（必做）：随机生成 20+ 场况（含复杂防守/听牌判断/鸣叫判断/役满机会），模型输出动作概率与理由特征，交付人类查验。
- 在线测评（可选，需人类决策）：接 Tenhou 需要账号与登录令牌；接雀魂需要协议逆向/账号授权。默认以离线 + 人工抽查为准，在线接入等确认后单独排期。

### 8.4 可解释性设计（一等公民）
- 决策分解因子：向听数/进张数（ukeire）、对每家已见牌的安全度（danger/suji/kabe）、得分期望（含宝牌/赤宝）、剩余巡数与场况（点数顺位、亲家、立直棒）。
- 输出结构：每次决策附带 top-k 候选动作及逐因子得分 + 最终概率 + 模板化自然语言理由（如'切 9m：保持向听不变，进张 12 张，且 9m 为对下家双筋安全牌'）。
- 实现：规则特征因子化计算器 + 模型注意力/梯度归因（可选）双通道，专家查验时直接读理由。
- 与训练目标不冲突：解释因子只读（不参与反向传播主路径），避免牺牲策略精度。
