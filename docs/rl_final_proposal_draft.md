## 0. 修订原则与"效果铁律"（与 critic 对齐的边界）

优先级：**创新 > 效果 > 解释性 > 工作量**，但"创新 > 效果"绝不等于"为创新牺牲效果"。本草案对每个创新点强制四条约束：

1. **效果指认**：每个创新点必须显式指定它服务的"效果指标"（弃牌 top-1 / 放铳率 / 胜率 / 平均顺位 / 解释质量分）与**预期提升量级**，无效果指认的创新不进入论文主贡献。
2. **独立消融 + 量化门槛（critic R5 + auditor 点 2，主线）**：每个创新点必须能独立 on/off（**一次只开一项的受控消融**，同 seed、100 局×3 种子 CI + **配对种子 + 置换检验**，验收口径沿用 `eval v2`）；**"大幅"显式量化（R5）** = win_rate +3pp 且 CI 下界 ≥+1pp，或放铳率相对下降 ≥5%（auditor 曾建议胜率 3%/放铳率 10%，差异见 §7 争议标注，待裁定）；消融不达标 → 该点降级为附录实验或放弃，不得留在主贡献。
3. **阶段推进门槛**：任何阶段不得降低上一阶段基线效果——防守阶段（③）验收 = **放铳率下降且胜率不降**；剥削阶段（①）验收 = **对风格化对手池胜率提升且对均衡基线不降**（沿用 roadmap D1/D2 决策）。
4. **正确性优先**：M0 必修 4 项（T1 奖励尺度 / T2 熵掩码 / A1-mask / T9 sanity）是效果的底座，优先于一切创新；创新全部作为"叠加层"，逐项独立归因。

## 2. 差距分析：从"可执行方案"到"论文级贡献"

当前方案的弱项不是工程，而是**"创新点尚未被包装为可验证的论文贡献"**：

| 差距 | 现状 | 论文需要 |
|---|---|---|
| 创新点有实现、无"效果证据" | ②③④ 只有架构描述，无量化效果声明 | 每个贡献点附消融表 + 预期提升量级 |
| 创新点互相独立、无主线 | ②③④ 各说各话 | 统一叙事（事件因果推理 → 信念读牌 → 座位等变） |
| 无 benchmark 资产 | 数据/引擎/评测协议散落各处 | 标准化基准 = 论文实验底座 + 开源引流抓手 |
| 无部署路径 | 50 残差块×284 通道，实时不可行 | 蒸馏小模型 + 延迟指标（应用目标） |
| 解释性未接入创新 | `explain.py` 因子计算器已有，模型输出未结构化对接 | rationale/factors 忠实归因（专家通道硬要求） |

**修订核心动作**：不新增"研究级方法"（critic 已正确判定无需），而是把已有差异化点升级为**可消融、可量化、可复现**的论文贡献，并用 benchmark + 可解释输出 + 部署路径补齐三目标。

### 2.1 效果口径声明（critic R2，论文第一攻击点——必须进正文）

**现状风险**：77.28% 是自家 holdout 的 discard top-1；Suphx 76.7% 是其 50K 测试集同指标——**口径不同，任何"超 Suphx"声称都会被审稿人一击致命**。

**二选一策略（需 captain 拍板）**：
- **方案 A（推荐，若 Suphx 测试集可获取/可重建）**：共用基准复测——同一预处理下复测双方 top-1，直接可比；
- **方案 B（兜底）**：论文所有对比标注 **"口径不同仅供参考"**，不以"超 Suphx"为卖点；主证据改为 RiichiBench 统一协议下的模型间对比（表1）+ 外部锚点对打（§5.3）。

**口径锁定（写死）**：top-1 = **合法弃牌动作分类准确率**（动作掩码内 argmax 是否等于人类动作，非法动作不计入，与 §5.1 一致）。

## 3. 最终版创新点清单（每个：论文贡献点 / 效果预期 / 实现要点 / 工作量）

### C1. ② 事件因果注意力（论文贡献 #1：架构）—— 强化为主贡献
- **论文贡献点**：显式建模麻将**公开事件时间线的因果结构**（事件级 token + 因果掩码 + recency 计数 + 逐通道门控融合）。对照：Suphx 无事件注意力（CNN 主干）、Tjong 用静态帧 transformer、JongMaster 用 CNN+LSTM+SA 但无事件因果结构。**麻将 AI 首次**。
- **效果预期**：正确性修复（A1-mask）保证不降效果；recency+pool 增强预期弃牌 top-1 **+0.3~1.0pt**（相对位置编码经验量级）；RL 阶段信息密度提升（防守读牌输入质量）；注意力图 → 解释质量分提升。
- **实现要点**：`attn_modules.py`（A1 拆两提交，已在 M0）；**新增**注意力图导出接口（供 `explain.py` 引用，接入 `model_runner.predict` 的 rationale 字段）。
- **工作量**：A1 已含于 M0（1~1.5 人·天）；可视化导出 **+0.5 人·天**。

### C2. ③ 信念危险度分解（论文贡献 #2：方法 + 可解释）—— 强化为主贡献
- **论文贡献点**：危险度 = **P(听牌) × P(待牌)** 的可分解信念读牌——直接监督（自对弈 ground truth，他家手牌已知）、可解释（因子可审计）、可迁移（防守决策）。对照：JongMaster 只做整体防守改进，无显式危险度分解；麻将 AI 无先例。
- **效果预期**：防守阶段验收 = **放铳率 -3~5% 且胜率不降**（JongMaster 参照 -5.12%）；危险度因子直接支撑专家通道 rationale（解释质量目标 ≥4/5）。
- **实现要点**：`BeliefDangerHead` + `gen_danger_data.py`（已有 18.7K 点验证）+ 相对座位序修正（critic §2.3-③-1）；负样本池复用校准方法论。
- **工作量**：阶段2 已有；论文侧消融 +0.5 人·天。

### C3. ④ 相对座位序等变（论文贡献 #3：理论）—— 强化为主贡献
- **论文贡献点**：**首次系统分析麻将座位等变的两种形式**（全置换等变 vs cyclic 旋转等变），证明全置换等变丢失"下家/对家/上家"相对顺序结构（鸣牌优先级依赖），提出 seat-relative conditioning 恢复，并与 Suphx 的 seat invariance 做形式化对照。这是 critic 认定的"最有价值的架构发现"，升级为理论贡献点。
- **效果预期**：规则性知识正确性（下家优先鸣牌等）；**样本效率提升**（等变归纳偏置，同等数据下收敛更快）；声明决策一致率提升。
- **实现要点**：`OpponentEquivariant` 聚合前加相对座位 one-hot；**消融三档：全置换 vs cyclic vs seat-relative**（同 seed）；**等变不变性测试**（打乱对手身份标签 → 决策分布应不变，auditor 点 3，主线证据）。
- **工作量**：阶段2 已有；消融 +0.5 人·天。

### C4. 阶段3 剥削性打法（论文贡献 #4：麻将空白，bonus section）—— MVP 化
- **论文贡献点**：麻将首个显式剥削框架（roadmap 调研确认 Mortal/AlphaJong/Naga/kanachan/Hydra 均无显式对手建模/剥削）。拆 3 子目标防烂尾：**对手画像 → 攻守权衡 → best-response 验证**。
- **效果预期**：对风格化对手池胜率 **≥66%**（R3）且相对均衡基线提升显著；攻守权衡输出同时服务应用（攻/守/半攻半守 + EV 分解）。
- **实现要点**：对手风格摘要 `FiLM`（④-2 预埋阶段1 summary 通道）；攻守权衡头（C6 复用）；best-response 对手池（复用 T3 池机制）；**剥削红线（R4）**：报告池内收益 / 池外泛化 / 可剥削度（Nash-gap 估计），训练池与评估池严格分离。
- **工作量**：新增 **+1.5~2 人·天（MVP）**；若预算不足降级为"对手画像分类器初步研究"（+0.5 人·天）进论文 §6 preliminary。

### C5. RiichiBench 基准发布（论文贡献 #5 + 开源引流抓手）—— 新增，核心推荐
- **论文贡献点**：**首个大规模标准化立直麻将决策基准**：55.9M 决策点（110K 局）+ oracle 99.95% 验证引擎 + 分层评测协议 L0-L4。提供 Suphx/Tjong/JongMaster 的可复现对比口径（消除"各论文自报指标不可比"问题）。
- **效果预期**：不直接提升模型效果，但**直接服务三目标中的论文（实验底座）+ 开源（引流）**；benchmark 论文（NeurIPS D&B / 数据论文）可独立成篇或作为主论文配套。
- **实现要点**：切 benchmark 子集（+数据卡文档）+ 复用 `eval/run_eval.py` 打包发布接口 + **数据许可核查（auditor 点 4，C5 前置门）**：先核实 55.9M 天凤牌谱是否可再分发；**若不可再分发 → 发布 = 代码 + 权重 + 获取指引（牌谱来源/下载脚本）+ 特征级子集（决策点特征向量，不含原始牌谱）**，此为开源可复现保底方案；leaderboard 页面（开源配套）。
- **工作量**：新增 **+1.5~2 人·天**（含复现工程打包 0.5：种子确定性脚本 / LICENSE / 模型卡 / demo，auditor 点 5）。

### C6. 攻守权衡可解释模块（服务应用 + 解释性 + 剥削前置）—— 新增
- **论文贡献点**：决策 rationalization（攻/守/半攻半守 + EV 分解），与 C2 危险度因子拼接成完整 rationale 链；专家终评通道（通道A rationale/factors 硬要求）直接受益。
- **效果预期**：专家通道解释质量分目标 ≥4/5；攻守决策 EV 提升（L2 反事实 EV 可量化）。
- **实现要点**：`explain.py` 因子扩展 + `model_runner.predict` 输出结构对接（JSON schema 已定义）+ C4 攻守权衡头复用。
- **工作量**：新增 **+0.5~1 人·天**（与 C4 共享实现）。

### C7. 蒸馏部署小模型（服务应用 + 开源 quickstart）—— 新增可选
- **论文贡献点**：高效部署小节（可选）；精度-延迟权衡表。
- **效果预期**：推理延迟目标 **单步 <5ms（GPU）/ <20ms（CPU）**；天凤/雀魂 bot 实盘可用。
- **实现要点**：蒸馏脚本（大模型 50 块 → 8 残差块学生）+ 延迟基准 + mjai 协议对接（`src/tenhou/mjai_export.py` 已有）。
- **工作量**：新增 **+1 人·天（可选，最后做）**。

## 4. 论文定位

### 标题候选
- **主推**：*RiichiBench: Benchmarking Event-Causal Reasoning and Belief-Based Opponent Modeling for Riichi Mahjong*（以 benchmark 为锚，覆盖全部贡献）
- 备选1：*Event-Causal Attention and Belief-Based Danger Reading for Riichi Mahjong Agents*（以模型为锚）
- 备选2：*From Handcrafted Features to Belief-Based Reasoning: A Modular Riichi Mahjong Agent*（叙事型）

### 贡献列表（4+1）
1. **事件因果注意力架构**（C1）：事件级因果序列建模 + recency 编码 + 门控融合（麻将 AI 首次）。
2. **座位等变理论分析**（C3）：全置换 vs cyclic 等变的麻将信息结构分析 + seat-relative conditioning（首次系统化，含与 Suphx 对照）。
3. **信念危险度分解**（C2）：P(听牌)×P(待牌) 可解释读牌 + 直接监督 + 防守效果验证。
4. **RiichiBench 基准**（C5）：55.9M 决策点 + oracle 引擎 + 分层协议，统一对比口径。
5. **（bonus）剥削性打法初步研究**（C4）：对手画像 + 攻守权衡 + best-response 的麻将首探。

### 目标 venue（建议）
- 若 C5 为主锚：**NeurIPS Datasets & Benchmarks / ICLR D&B**（数据基准类，接收门槛对"资产完整度"友好）
- 若模型为主锚：**AAAI / IJCAI**（agent 类）或 **CAAI TIT / IEEE TNNLS**（期刊，Tjong 同赛道对照）

### 5.1 指标族统一口径（auditor 点 7，主线——定义写死，论文表头直接引用）

| 放铳率 deal-in | 放铳局数/总局数（按局统计） | L3 联赛 |
| 收支 net_points | 终局精算点数均值（settlement_pt 口径） | rl_spec.md §0 |
| 精度 top-1 | **合法弃牌动作分类**一致率（R2 口径锁定：动作掩码内 argmax；固定 200 局面趋势，仅监控） | 评测协议 §6-L1 |
| 信念头正确率 | 听牌/危险度 top-K 命中率 + ECE（阶段2 新增，验收 ECE ≤0.05，R3） | 待落 evaluation_protocol.md |

### 5.2 统计红线（critic R6，主线——防"口径漂移/事后挑选"攻击）

1. **固定 eval seed 集**：验收用 seed 集开训前冻结，写入配置文件，禁止运行中更换；
2. **配对种子消融**：所有 on/off 消融用同一 seed 集合配对比较（配对检验，非独立样本）；
3. **验收指标 run 后一次计算**：验收口径指标在完整 run 结束后一次性计算并冻结，禁止"看结果再选指标"；
4. **T5 校准集与验收集分离**：阈值校准用校准集，验收/论文表用独立验收集，二者零重叠；
5. **t7 泄漏审计**：沿用现有 t7 泄漏检查（留出集零泄漏），作为论文提交前必过门。

### 5.3 外部强度锚点（critic R1，主线——效果从"自证"升级"外部可比"）

- **做法**：包装 mjai bot（与 C7 复用 mjai 对接），与强开源 bot **Mortal / kanachan / akochan / Naga（可用者）** 固定协议对打，报告 win_rate / 平均顺位 / Elo；
- **意义**：现有 66% 验收是"对自家 SL 基线"的自证；外部锚点让效果具备**社区可比性**（Mortal 等在天凤/雀魂有公开强度），论文审稿与开源关注度双加分；
- **工作量**：mjai bot 包装 +0.5 人·天（主线，与 C7 共享）；对打实验矩阵（每对手 2000 局）视预算 → 论文表8（附录或主线，建议至少 2 个可用 bot 进主表）。

## 8. 工作量预算与取舍（9~11 人·天可微调，理由如下）

### 微调理由（为什么从 9~11 上调到 12~15）
1. **既有 9~11 人·天只买到"效果达标"，买不到"三目标"**：critic 已诚实裁定 ~20 项是标准落地、创新度 70/100——若预算不变，论文贡献 = 已有实现的"裸奔"（无消融表、无 benchmark、无可视化），不构成"可发表"。
2. **新增的 3~4 人·天几乎全是"实验/包装"而非"新研究"**：C2/C3 消融复用阶段2 训练产物，C5 复用已有数据/引擎/评测协议，C1 复用 A1 实现——边际成本远低于其论文+开源收益。
3. **若必须严格 9~11**：裁剪顺序 = 砍 C7（1 人·天）→ C4 降级为初步研究（省 1~1.5）→ C6 并入 C4（省 0.5）→ C5 降为"数据卡+leaderboard 页"（省 0.5）→ 最低仍保留 C1-C3 消融（1.5 人·天），**即 9~11 严格版的底线是"创新点消融表"，benchmark 与剥削留作论文未来工作**。
4. **风险对冲**：创新打包与 M0/M1 并行（消融/可视化/benchmark 文档不依赖训练完成），不阻塞主训练时间线。

### 执行顺序建议
M0 必修（4 项先行）→ M1 训练 → **并行**：C1 可视化 + C5 打包 + C2/C3 消融协议设计 → M2 验收 → M3 消融执行（C2/C3 归因）→ 可选 C4/C6/C7。
