# C5 数据许可合规核查（data_license_check）

> 依据: rl_final_acceptance.md 通过条件 3（开跑前 C5 合规核查先行）；judge No-Go 阻塞 2；auditor Q7 裁定（保底方案）。

## 1. 数据来源
- 天凤（Tenhou.net）凤凰桌 mjlog 牌谱（110,254 局 / 55,950,217 决策点），本地解析自 data/raw/mjlog
- 处理产物: records（schema §2 决策点 JSONL）、张量化 tensor（284 通道）、负样本池

## 2. 许可结论
- 天凤牌谱再分发: **无明确官方授权，属灰色地带**（社区先例 Mortal-298k 不等同合规）
- 判定: **完整原始牌谱不可直接再分发**

## 3. 可再分发判定（保底方案，auditor Q7 裁定）
默认发布物（不依赖原始牌谱再分发）:
1. 代码（自写，MIT/Apache-2.0）+ 模型权重
2. 数据获取指引（mjlog 来源说明 + 自解析工具链）
3. 特征级决策点子集（张量可逆性低、风险可控）
4. 引擎自对弈生成数据（完全自有版权，补充）

## 4. 切换预案
- 若发布前完成官方条款核查且确认可分发 → 升级为完整记录子集
- 若不可 → 维持保底方案；C5 论文价值不依赖完整数据（协议+oracle 引擎+leaderboard 才是贡献）

## 5. 第三方审计 + AGPL 防线
- mjai.app-main: AGPL-3.0 → 不引入其代码（转换器自写，参考协议格式）
- tenhou-to-mjai: 独立项目（借鉴时核验许可）
- shanten_tmp.py: mahjong 库封装（MIT）——发布前逐一审计
- 发布前 0.5 人·天条款核查 + 数据卡（来源/许可/统计粒度/获取指引）

## 结论
- 合规策略: 保底方案（代码+权重+获取指引+特征子集+自对弈数据），完整数据不设为前置
- 状态: 策略已定，发布前最终条款核查列入 C5 交付清单（judge B2 判定：满足五要素）
